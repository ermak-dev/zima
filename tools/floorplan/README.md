# Полигональная карта из occupancy grid (#70)

Офлайн-инструмент превращает сетку SLAM в полигональную карту: стены,
комнаты, дверные проёмы и препятствия. Робот, движение и сеть не нужны.

## Вход

Сетка в формате адаптера MRPT (`{"op":"map"}`): `x_min, y_min, res, w, h`
и `cells` — CSV построчно с ростом y (0..100 — занятость в процентах,
`-1` — неизвестно). Получить её из записи прогона:

```sh
python3 -I tools/slam-replay/hardware.py /private/run/player.jsonl \
  --adapter tools/mrpt-adapter/adapter --lidar-yaw-deg 0 \
  --map-out /private/run/map.json
```

Файл создаётся `0600` и никогда не перезаписывается.

## Запуск

```sh
python3 -I tools/floorplan/floorplan.py /private/run/map.json \
  --geojson out.geojson --svg out.svg --report report.json
```

Все выходные файлы создаются новыми (`0600`). В `stdout` печатается отчёт.

## Выход

GeoJSON (FeatureCollection, координаты в метрах системы карты):

- `wall` — LineString, осевые линии стен;
- `door` — LineString с `width_m`, проёмы 0,45–1,0 м между двумя комнатами;
- `room` — Polygon с `area_m2` (площадь полигона, не счётчик клеток)
  и `edges` с флагом `observed` для каждого ребра;
- `obstacle` — Polygon, необъяснённые занятые компоненты (мебель),
  никогда не стены и не границы комнат.

SVG содержит те же слои для быстрого просмотра. Отчёт JSON: оценка угла
доминирующего направления, доля объяснённых клеток стен, медиана/p95
расстояний занятых клеток до линий, число необъяснённых клеток и доля
ненаблюдённого периметра комнат.

## Метод

1. **Доминирующее направление** — перебор поворота 0..90° с шагом 0,25°
   (уточнение 0,05°): ищется угол, при котором занятые клетки максимально
   слипаются в осевые линии (сумма квадратов верхних пиков гистограмм
   координат). Дальше работа идёт в повёрнутой системе.
2. **Стены** — проекции занятых клеток: клетка голосует только за
   перпендикулярную её градиенту ось; перпендикулярные бины в пределах
   3 клеток сливаются в медианную линию; серия клеток в линии с допуском
   разрыва ≤ 2 клеток даёт отрезок.
3. **Комнаты** — свободное пространство минус бар 0,45 м вдоль стен
   и неизвестной границы; связные компоненты ≥ 0,5 м² — ядра комнат;
   отрастание обратно в бар по ближайшему ядру (не дальше 0,5 м, только
   по свободным клеткам с известной комнатой-источником).
4. **Двери** — разрывы 0,45–1,0 м между коллинеарными отрезками стен,
   по обе стороны которых лежат разные комнаты.
5. **Препятствия** — необъяснённые занятые компоненты ≥ 8 клеток.
6. **Границы комнат** — обход контура маски, упрощение Дугласа—Пекера,
   ортогонализация: рёбра в допуске 0,35 м от линий стен переносятся на
   них, углы пересчитываются пересечением; при изменении площади более
   чем на 30% возвращается исходный полигон.
7. **Честность** — неизвестные клетки не становятся ни стенами, ни полом:
   ребро полигона, выходящее к неизвестности, помечается `observed:false`,
   и стена в этом месте не рисуется.

## Ограничения

- Диагональные (неосевые) стены пока не извлекаются как отрезки: их клетки
  остаются необъяснёнными; при большой доли таких стен ориентация сцен
  с несколькими доминирующими направлениями может быть неточной.
- Стекло и зеркала искажают исходную сетку SLAM — инструмент наследует
  эти ошибки и не исправляет их.
- Только numpy/scipy; новых зависимостей нет.

## Проверки

`python3 -m unittest tests.test_floorplan` — синтетические сцены
(прямоугольник, Г-форма, дверь, шум, поворот на 17°, разрыв стены,
столб, враждебные сетки, права на выходные файлы, `--json`-режим).

## Живой слой панели (#83)

Тот же инструмент вызывается сервером с `--json` (сетка на stdin, один JSON
на stdout) по кнопке «Пересчитать карту» в панели. Инструмент ничего не
знает о сервере и панели; меняется только способ вызова. Путь можно
переопределить переменной `ROBOT_FLOORPLAN_TOOL` (используется тестами).
