# MRPT SLAM-адаптер

Отдельный C++-процесс с протоколом «строка JSON на stdin — строка JSON на
stdout». Изолирует зависимости MRPT от Rust-сборки: сбой адаптера не роняет
сессию робота, сервер перезапускает его при необходимости.

## Сборка

MRPT 2.14.8 собирается из исходников один раз; команды воспроизведения — в
`../.gitignore` (каталог `third_party/` исключён из git целиком).

```sh
g++ -std=c++17 -O2 -I third_party/install/include \
  $(for d in third_party/install/include/mrpt/*/include; do echo -I$d; done) \
  adapter.cpp -o adapter -L third_party/install/lib \
  $(ls third_party/install/lib/libmrpt-*.so | sed 's|.*lib|-l|;s|\.so||') \
  -Wl,--disable-new-dtags -Wl,-rpath,'$ORIGIN/third_party/install/lib'
```

`--disable-new-dtags` обязателен: он пишет старый `DT_RPATH`, который
загрузчик применяет и к транзитивным зависимостям (libmrpt-slam ищет
libmrpt-config). Современный `DT_RUNPATH` для этого не работает — адаптер
упадёт с «cannot open shared object file» при запуске без
LD_LIBRARY_PATH.

## Протокол

- `{"op":"start_mapping"}` — включить построение карты (CMetricMapBuilderICP,
  матчинг по карте точек).
- `{"op":"load_map","path":...}` — загрузить simplemap и включить локализацию
  (MCL, 300 частиц, глобальный сброс по свободным клеткам при старте).
- `{"op":"update","scan":{"angles":[...],"ranges":[...]},"range_max":R,
  "sensor_x":X,"odom":{"dx":..,"dy":..,"dyaw":..}}` — один скан +
  приращение одометрии (в системе предыдущего кадра робота). Каждый луч
  несёт свой угол в base_link; дальности отсчитываются от LDS в точке
  `(sensor_x, 0)`. Ответ: `pose` (x,y,yaw) и `quality` (в localize — от
  разброса частиц; в mapping всегда 1.0).
- `{"op":"local_reset"}` / `{"op":"global_reset"}` — перезапуск частиц в
  окрестности последней позы ±0.5 м / по всей карте.
- `{"op":"map"}` — сетка занятости, обрезанная по наблюдённой области:
  `x_min, y_min` (угол первой клетки), `res`, `w`, `h`, `cells` — CSV
  построчно с ростом y; значение — вероятность занятости в процентах
  (0 свободно … 100 стена), `-1` — клетку ещё не видели. Внутри MRPT
  хранит обратную величину, P(свободно); адаптер её переворачивает.
- `{"op":"save_map","path":...}` — сохранить simplemap (только в mapping).

Углы сканов приходят в base_link: сервер добавляет смещение LDS
(`player_bridge::scan::LDS_YAW_DEG`), нормализует в [-π, π) и отбрасывает
попадания в корпус (< `LDS_RANGE_MIN`). В MRPT у скана нет угла на луч:
направление выводится из номера (−π + i·2π/(N−1)). Поэтому адаптер
раскладывает лучи по 721 фиксированной ячейке (0.5°); пустые ячейки
невалидны и не считаются свободным пространством. В грид пишутся только
попадания ближе 5 м: редкие дальние лучи рисуют веерные полосы, а не стены.
MRPT-логи уходят на stderr (stdout занят протоколом);
`MRPT_ADAPTER_DEBUG=1` у адаптера включает DEBUG-уровень.

## Проверка

- Геометрия карты и семантика `map` на синтетических комнатах (прямые
  стены при выпавших лучах, плечо лидара при развороте, обрезка и `-1`,
  предел дальности): `python3 -I test_adapter.py` из этого каталога.
  Без собранного `adapter` тесты пропускаются.
- Cargo-интеграция с реальным адаптером:
  `LD_LIBRARY_PATH=third_party/install/lib cargo test --manifest-path
  ../../crates/Cargo.toml -p robot-server --test server real_adapter --
  --ignored`.

## Известные ограничения

- ICP-билдер без loop closure: карты квартир с длинными петлями будут
  дрейфовать; маршрут первой сессии строить «ёлочкой».
- Симметричные комнаты (квадрат без признаков) дают неоднозначную
  глобальную локализацию — фильтр может уверенно сходиться к повернутой
  гипотезе. Для живой квартиры это редкость, на синтетике — обязательно.
- `save_map` пишет simplemap; отдельного экспорта в PNG нет (карта для
  панели приходит через `map` в JSON).
