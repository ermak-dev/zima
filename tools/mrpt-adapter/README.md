# MRPT SLAM-адаптер

Отдельный C++-процесс с протоколом «строка JSON на stdin — строка JSON на
stdout». MRPT-логи перенаправлены на stderr. Работает на хосте; сборка и
тесты ниже не подключаются к роботу и не запускают сервер приложения.

## Сборка

Нужны C++17-компилятор и уже установленный MRPT 2.14.8 в
`third_party/install`. Скрипт ничего не скачивает и не меняет `third_party`.

```sh
bash tools/mrpt-adapter/build.sh
bash tools/mrpt-adapter/build.sh --output /tmp/robot-mrpt-adapter
```

Без `--output` пересобирается `tools/mrpt-adapter/adapter` из текущих
исходников. В режиме `--test` результат по умолчанию — отдельный
`tools/mrpt-adapter/adapter-tests`: рабочий адаптер не перезаписывается. `CXX` переопределяет `g++`. Скрипт использует абсолютный
`DT_RPATH` к локальной установке MRPT: бинарник из `/tmp` тоже работает без
`LD_LIBRARY_PATH`. После перемещения репозитория его нужно пересобрать.
`--disable-new-dtags` нужен для поиска транзитивных зависимостей MRPT.

## Протокол

- `{"op":"start_mapping"}` — новая карта, нулевая поза, пустые облако,
  simplemap и постоянная occupancy grid. Сбрасывает прежний mapping/MCL.
- `{"op":"load_map","path":...}` — загрузить непустой simplemap,
  один раз восстановить grid и включить MCL с 300 частицами и глобальным
  распределением по свободным клеткам. Ошибка чтения не заменяет текущую карту.
- `{"op":"update","scan":{"angles":[...],"ranges":[...]},"range_max":R,
  "sensor_x":X,"odom":{"dx":..,"dy":..,"dyaw":..},"stamp":T}` — один скан
  и приращение одометрии в системе предыдущего кадра робота. `stamp`
  необязателен: передаётся сервером только при проверенной семантике времени.
  Он используется без выдуманного шага между сканами и не объявляется UTC.
  Без него observation получает фактическое время обработки на хосте,
  не время физического измерения. Пустые, несовместимые или некорректные
  массивы дают `ok:false` до изменения карты/позы. Измерения не приводятся
  из строк или `null` к нулям; дальности вне `(0, range_max]` отбрасываются.
- `{"op":"local_reset"}` / `{"op":"global_reset"}` — перезапуск MCL в
  окрестности последней позы ±0.5 м / по всей карте.
- `{"op":"map"}` — grid, обрезанная по наблюдённой области: `x_min, y_min`
  — угол первой клетки, `res`, `w`, `h`, `cells` — CSV построчно с ростом y.
  Значения — занятость в процентах (0 свободно … 100 стена), `-1` — неизвестно.
  Пустая новая карта имеет `w=h=0`, `cells:""`.
- `{"op":"save_map","path":...}` — сохранить доверенные keyframes в
  CSimpleMap (только mapping). Экранированные пути JSON поддерживаются.
- `{"op":"ping"}` — `mode: idle|mapping|localize`.

### Геометрия и insertion

Углы приходят уже в `base_link`: сервер добавляет монтажный yaw LDS.
Дальность отсчитывается от `(sensor_x, 0)`, поэтому реальная точка робота —
`(sensor_x + r*cos(angle), r*sin(angle))`. Именно эти XY-точки без
интерполяции и без фильтра соседних угловых ячеек передаются в `CICP`.
Опорное облако содержит точки доверенных keyframes в системе карты.
`CMetricMapBuilderICP` не используется: его внутренний `sensedPoints`
с фильтром 2 см терял одиночные лучи после угловых пропусков.

Для occupancy и сохранения остаётся `CObservation2DRangeScan` с 721
ячейкой (0.5°): коллизии берут ближайший луч, неизвестные угловые промежутки
остаются невалидными, а не становятся свободным пространством. Grid
пополняется при вставке keyframe; `map` лишь экспортирует существующую
сетку, не проигрывает историю. При загрузке simplemap история вставляется
однократно. Попадания дальше настроенного insertion range не рисуются.

Первый непустой скан задаёт начальную геометрию, но это не успешная
ICP-коррекция. Далее каждый скан сопоставляется с опорным облаком из
предсказания по одометрии. При недостатке точек (<6 в любом облаке), низком
goodness или неконечном результате сопоставление отвергается: сохраняется
предсказание по валидной одометрии, новая геометрия не вставляется.
Принятое сопоставление добавляет keyframe только после достижения линейного
или углового порога относительно последней вставки. Дополнительно, без
достоверной компенсации кадра приращение одометрии более 0.08 м или 8°
приостанавливает вставку **в grid и опорное облако**, но не расчёт позы ICP.
Это консервативный бюджет допуска keyframe между обработанными кадрами,
не оценка точного движения внутри оборота и не ограничение колёс.
Ответ получает `mapping_paused:true`, `tracking:degraded` и причину
`uncompensated_motion`; следующий достаточно спокойный кадр снова может
пополнить карту. Первый кадр остаётся bootstrap и сам может быть искажён.

Необязательный `motion_compensated:true` разрешён только для доказанно
одномоментного либо уже приведённого к общему времени скана. Player-путь
этот флаг не выставляет: времён лучей пока нет. Офлайн-генератор выставляет
его для своей явной мгновенной модели и oracle-deskew, но не rolling-сканов.

### Диагностика update

Ответ содержит `ok`, `pose:{x,y,yaw}`, `quality`, `tracking` и `diagnostics`.
`quality` равен фактическому ICP goodness, а без ICP — `null`, не 1.0.
`tracking`: `initializing` при bootstrap, `tracking` при принятом ICP,
`degraded` при отказе. Ошибки протокола возвращают `ok:false,error`.

Поля `diagnostics`:

- `input_points` — длина входных массивов; `used_points` — число валидных
  реальных XY-точек, переданных в ICP; `reference_points` — число точек
  опорного облака **до** обработки этого скана.
- `accepted` — принята ли ICP-коррекция; `reason` — `bootstrap`,
  `insufficient_points`, `accepted`, `low_goodness`, `nonfinite_result`
  `uncompensated_motion` или `mcl_update`.
- `goodness` — результат MRPT `[0,1]` либо `null`; `iterations` — число
  итераций MRPT либо `null`; `duration_ms` — фактическое время update.
- `correction:{x,y,yaw}` — разница результата ICP и предсказания: x/y в
  осях карты, yaw нормализован. Это предложенная коррекция, в том числе
  при отказе; без сопоставления `null`.
- `covariance` — ковариация предложенной позы из MRPT PDF, 9 чисел
  построчно (x,y,yaw), либо `null`, если недоступна/неконечна.
- `correspondences` — измеренное число пар после предложенного преобразования:
  отдельный `determineMatching2D` по всем sensed-точкам без децимации.
  Порог `correspondence_threshold_m` равен меньшему из начального порога ICP
  и его конечного порога расстояния. Это не восстановление числа пар из
  округлённого goodness и не счётчик последней внутренней итерации ICP.
- `residual_rms` — RMS расстояний этих явно отобранных пар, в метрах;
  без пар или без сопоставления — `null`.
- `mapping_paused` — приостановлена ли вставка из-за большого движения
  неподтверждённого/некомпенсированного кадра; принятие коррекции ICP
  и разрешение пополнить карту — разные результаты.

MCL сохраняет прежний алгоритм и spread-прокси в отдельном
`localization_quality` (0…1). Он не выдаётся за ICP: `quality`, `goodness`,
`iterations`, `correction`, `covariance`, `residual_rms` равны `null`,
`accepted:false`, `reason:mcl_update`. Его `reference_points:0` относится
к отсутствию ICP-облака, а не к пустоте загруженной occupancy map.

### Конфигурация

Настройки читаются при `start_mapping` / `load_map`; некорректная настройка
даёт явную ошибку. Главный CLI экспортирует их из `[slam]` TOML.

| Переменная | По умолчанию | Допустимо |
| --- | --- | --- |
| `ROBOT_SLAM_ICP_MIN_GOODNESS` | 0.30 | 0…1 |
| `ROBOT_SLAM_ICP_MAX_ITERATIONS` | 40 | целое 1…1000 |
| `ROBOT_SLAM_ICP_THRESHOLD_DIST` | 0.75 | 0.001…10 м |
| `ROBOT_SLAM_ICP_DECIMATION` | 1 | целое 1…1000; внутренний шаг соответствий MRPT |
| `ROBOT_SLAM_INSERTION_LINEAR` | 0.10 | 0…10 м |
| `ROBOT_SLAM_INSERTION_ANGULAR_DEG` | 10 | 0…180° |
| `ROBOT_SLAM_GRID_RESOLUTION` | 0.05 | 0.01…1 м |
| `ROBOT_SLAM_MAX_INSERT_RANGE` | 5.0 | 0.1…100 м |
| `ROBOT_SLAM_MAX_UNCOMPENSATED_TRANSLATION` | 0.08 | 0…1 м между кадрами |
| `ROBOT_SLAM_MAX_UNCOMPENSATED_ROTATION_DEG` | 8 | 0…180° между кадрами |

Общий TOML дополнительно ограничивает некоторые диапазоны консервативнее,
например число итераций 1…200 и децимацию 1…16; проверка выполняется до
подключения к роботу. Прямое окружение адаптера предназначено для офлайн-экспериментов.

Таймаут адаптера, возраст позы, pairing timestamps и deskew принадлежат
Rust-серверу, не этому процессу. Наличие `stamp` не доказывает проверенность
часов датчиков. Здесь нет синтетического scan clock или автоматического
приписывания beam timing. `MRPT_ADAPTER_DEBUG=1` включает логи ICP.

## Офлайн-проверка

Из корня репозитория:

```sh
bash tools/mrpt-adapter/build.sh
python3 -I tools/mrpt-adapter/test_adapter.py
bash tools/mrpt-adapter/build.sh --test --output /tmp/mrpt-adapter-test
/tmp/mrpt-adapter-test
shellcheck tools/mrpt-adapter/build.sh
```

Для тестирования отдельной сборки используйте явный выбор бинарника:

```sh
bash tools/mrpt-adapter/build.sh --output /tmp/mrpt-under-test
MRPT_ADAPTER_BIN=/tmp/mrpt-under-test python3 -I tools/mrpt-adapter/test_adapter.py
```

Python проверяет dropout, вращение с плечом LDS, неизвестные сектора,
намеренно ошибочную одометрию, сохранность облаков, отказ без загрязнения
карты, восстановление, diagnostics, конфигурацию, save/load/MCL и сборку
в выбранный каталог. C++ проверяет исходные XY при коллизиях angular bins,
время, строгий JSON и эквивалентность incremental grid восстановлению из
simplemap. Отсутствующий выбранный бинарник не считается успешным прогоном
новых тестов.

Cargo-интеграция с настоящим адаптером (локальные fake-датчики):

```sh
cargo test --manifest-path crates/Cargo.toml -p robot-server --test server real_adapter -- --ignored
```

## Ограничения

- Нет loop closure; при длинных петлях возможен дрейф.
- Симметричные комнаты дают неоднозначную глобальную MCL-локализацию.
- Экспорт grid всё ещё сканирует текущую сетку для обрезки и сериализации;
  устранена повторная вставка истории, а не стоимость отправки большого JSON.
- ICP reference cloud и simplemap растут с числом доверенных keyframes.
- Очень бедный первый скан (<6 точек) не создаёт достаточную опору для ICP;
  следующий полноценный скан завершает bootstrap без заявления об
  ICP-коррекции. Его начальная поза всё ещё зависит от одометрии.
- Сохранение остаётся в simplemap, отдельного PNG-экспорта нет.
- Офлайн-тесты не подтверждают физическую калибровку LDS, timing драйвера
  или качество SLAM на живом роботе.
