платный OpenRouter с ключом из приватного `.env`. Движение/уборка не запускались.

## Найденные и исправленные дефекты TTS

1. Два первых запроса с `stream=true` и `format=wav` получили HTTP 400:
   выбранный провайдер принимает в этом режиме только `pcm16`.
   Добавлены явные `audio_format` / `pcm_sample_rate`, оборачивание PCM в WAV
   и ресемплинг. Этот профиль проверен с PCM 24 кГц/моно.
2. Простая текстовая реплика побуждала аудиомодель **ответить**, а не озвучить
   её дословно. Первый полученный звук оказался разговорным ответом.
   Задание теперь передаётся как JSON `read_verbatim`; runtime по умолчанию
   требует совпадения расшифровки с заказанным текстом до воспроизведения.
   Отсутствие transcript/несовпадение/обрезка лимитом — ошибки, не успех.
3. Добавлены ограничение выходных токенов (512 в проверке), очистка telemetry
   перед каждой попыткой и числовой `last_usage`. Автоматических платных повторов нет.
4. Добавлено безопасное чтение только `OPENROUTER_API_KEY` из явно указанного
   `tts.env_file`, без source/исполнения и без изменения GitLab-загрузчика.

Полный живой запрос через `/robot/speech/say` синтезировал аудио за 2,759 с и
вернул `cost=0.0001974`. Две другие завершённые генерации стоили $0,000423
(первый разговорный ответ) и $0,000195 (исправленный дословный синтез).
**Сумма возвращённой стоимости трёх завершённых генераций: $0,0008154.**
Два HTTP 400 не вернули usage; сумма не является аудитом всего аккаунта.

Заказанный исправленный текст, provider transcript и независимое локальное ASR
совпали: «Проверка голосового ответа». Длительность эталона — 2,35 с.

## Усиление и микрофон OpenIPC

Исходные настройки: `audio.volume=40`, фактический ACODEC gain −1,5 dB.
На установленной старой прошивке `GET /api/v1/set?audio.volume=90` менял
показываемую конфигурацию, но не gain в `/proc/umap/acodec` и не сохранялся
как ожидаемая новая YAML-конфигурация. Поэтому ранние записи с именами
`speech-gain90.wav` нельзя считать подтверждённой калибровкой +28 dB.

Штатный путь web UI — `yaml-cli -s .audio.volume 90` и reload Majestic —
действительно установил +28 dB. Для окончательной записи gain проверен
**и до, и после** захвата. Независимый camera-local guard возвращал исходное
значение при завершении/таймауте; после теста проверены volume=40 и −1,5 dB.
Смена gain не автоматизирована в `camera_audio` и не выполняется при его старте.

При фактически применённом +28 dB и громкости динамика 0,65:

- фон, 2 с: AC RMS 355,74; −39,29 dBFS;
- контрольная запись, 6 с: AC RMS 582,59; −35,00 dBFS;
- пик 5369/32768, клиппинга нет;
- Whisper Base распознала часть слов;
- Whisper Small (CPU/int8, 2 потока) распознала контрольную фразу дословно
  из сырой записи за 2,008 с; фильтрация/нормализация для этого не потребовались.

Это подтверждает микрофонный тракт и ближнюю контрольную речь. Весь шестисекундный
интервал включает фон, поэтому разницу RMS нельзя выдавать за точный SNR
активной человеческой речи. Дистанции, человек, движение и ложные активации
в этом тесте не принимались. В пользовательском профиле вход и wake остаются
выключенными, `microphone_verified=false` до согласованной рабочей калибровки.

## AEC

На записанном реальном тракте SpeexDSP дал лишь около 0,60 dB снижения энергии
смеси после выравнивания эталона и адаптации. Смещение WAV относительно эталона
около 1,659 с включает организацию записи/транспорт и **не** является готовым
параметром `echo.delay_ms` между ROS-часами.

Нет приёмки реальной near-end речи, double-talk, стабильности задержки/дрейфа
и ложных активаций. **Full-duplex не включён, `echo.verified=false`.**
Синтетические офлайн-результаты не используются вместо этой физической проверки.

Без нового платного запроса можно воспроизвести проверенный кешированный эталон:

```sh
# Сам запуск не синтезирует речь и не включает лидар:
ROS_DOMAIN_ID=214 bin/robot audio run --config ~/.config/robot/audio-live-20261018.json
# Другой терминал, пока asset не истёк по TTL:
ROS_DOMAIN_ID=214 bin/robot audio play \
  5cb8c9c43d29939ba695ccbe65e5e99ce24f7816075b3199baacd937dda3d1a0 --volume 0.5
```

Для новой озвучки `audio say` выполнит платный запрос согласно профилю.
Для слышащего режима по-прежнему нужны питание камеры, осознанная настройка
усиления и порога VAD, выбранная пользователем русская фраза и принятые wake-веса.
