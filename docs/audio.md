# Звук и речь

Аудиоконтур работает на Python независимо от Rust-сервера панели. В нём нет
ROS, custom messages, wake word или обучения модели активации. Захват,
распознавание вручную начатой реплики, TTS и воспроизведение используют
один runtime. HTTP IPC доступен только на `127.0.0.1`.

## Процессы

```text
OpenIPC /audio.opus → Python audio service ↔ ffmpeg → PCM
                           │
                           └── SSH → robot-audio guard → playback worker → ALSA
```

Код находится в `python/robot_audio/`, CLI — в `bin/audio/cli.py`.
Обычный `audio run` не снимает RoboController, не включает LDS, не отправляет
команд движения и не зависит от `robot-server`.

## Безопасный запуск

Для захвата нужен ffmpeg. Локальное ASR требует отдельной установки
зависимостей из `requirements-audio.txt` и модели по явному локальному пути.
Сами модели автоматически не скачиваются. Для Piper TTS нужны Piper и
подготовленный голос. По умолчанию источники, выход и внешние вызовы выключены.

```sh
bin/robot audio check-config --config config/audio.example.json
bin/robot audio run --config config/audio.example.json
```

В другом терминале:

```sh
bin/robot audio status
```

Порт по умолчанию — 8086. Для отдельного экземпляра:

```sh
bin/robot audio run --config ~/.config/robot/audio.json --port 8087
bin/robot audio status --endpoint http://127.0.0.1:8087
```

`check-config` только проверяет схему; он не подключается к устройствам или
провайдеру. Рабочую конфигурацию и ключи храните вне репозитория. Старые
профили с разделом `wake` отклоняются: удалённые настройки не игнорируются
молча. Команд `train`, `evaluate` и флага `--experimental-wake` больше нет.

## Захват и запись

Один источник получает Opus по HTTP с OpenIPC-камеры, декодирует его через
ffmpeg в PCM 16 кГц, mono, S16LE. Сервис использует этот поток совместно
для записи и распознавания.

```sh
bin/robot audio listen on
bin/robot audio record ./test.wav --seconds 6
bin/robot audio listen off
```

Запись не перезаписывает существующий файл. Разрыв потока, пропуск блока,
смена stream ID или остановка прослушивания делают незавершённую запись
недействительной. Готовый WAV записывается приватно с правами `0600`.

Отдельная запись без запущенного сервиса:

```sh
bin/robot record ./test.wav --seconds 6
# Эквивалент: bin/robot audio capture ./test.wav --seconds 6
```

Эта команда не меняет режим робота и не требует LDS. Вход должен быть явно
включён в профиле; `--config` выбирает профиль. `--gain 0..90` — отдельное
явное разрешение на временную смену усиления камеры с восстановлением.
Не запускайте несколько независимых захватчиков без необходимости.

Учётные данные камеры берутся из `~/.config/robot/camera.netrc` (`0600`).
HTTP камеры не шифруется. Gain 100 ранее давал цифровые нули и клиппинг;
подтверждённый рабочий максимум — 90. Физическая приёмка микрофона не следует
из успешного импорта библиотеки или теста на фейках.

## Реплика без wake word

После явного включения входа и локального ASR:

```sh
bin/robot audio start
bin/robot audio status
```

`start` начинает одну реплику. VAD и ограничения времени определяют её
границы, а результат появляется в состоянии сервиса. `finish SESSION_ID`
подтверждает завершение обработки ответа для соответствующей сессии.

Активация словом и голосовое прерывание ответа удалены. Ручное начало
реплики отклоняется во время воспроизведения; сохраняются пауза после
динамика, ограничения длины, обработка разрывов и таймаут распознавания.

## Воспроизведение и TTS

```sh
bin/robot audio import ./notification.wav --config ~/.config/robot/audio.json
bin/robot audio play ASSET_ID --volume 0.35 --ttl 5
bin/robot audio say 'Проверка динамика'
bin/robot audio stop
bin/robot audio mute on
```

`import` подготавливает приватный asset-кеш и печатает идентификатор.
`play` принимает подготовленный ID, не URL или произвольный удалённый путь.
Ответ сообщает результат выполнения, а не только приём запроса. Отмена
считается подтверждённой только по результату backend; потеря SSH не
превращается в автоматический повтор потенциально уже звучащего файла.

Самостоятельный `bin/robot say` остаётся доступен без сервиса. Длинный текст
разбивается существующим механизмом на ограниченные части. Облачный TTS
требует явного согласия и отдельного ключа; никакие новые живые или платные
проверки не запускаются вместе с тестами.

На роботе используется один playback под lock. `robot-audio` запускается
через SSH на время операции, сохраняет микшер, следит за worker и
восстанавливает состояние при штатном окончании и поддерживаемых отказах.
BUSY не даёт права убивать чужой процесс. Потеря питания или SIGKILL самого
guard не покрываются гарантией восстановления микшера.

Helper собирается без обращения к роботу:

```sh
bash bin/audio/build.sh --output ~/.cache/robot/build/robot-audio-arm
```

Развёртывание меняет файл на роботе и требует отдельного разрешения:

```sh
bin/robot audio deploy --binary ~/.cache/robot/build/robot-audio-arm --confirm
```

## IPC

* `GET /status` — состояние без PCM и учётных данных.
* `POST /request` — JSON-объект с `command`.
* Команды: `status`, `listen`, `mute`, `start`/`utterance`, `finish`,
  `record`, `play`, `say`, `stop`.
* `listen`/`mute` используют `enabled`; `finish` — `session_id`;
  `stop` может указывать `task_id`.
* Длительности, размеры запросов, количество задач и очередь ограничены.
  Неизвестные поля и некорректные значения отклоняются до вызова runtime.
* `record` возвращает законченный WAV как base64; CLI проверяет формат
  и создаёт локальный файл без перезаписи.
* Ctrl-C/SIGTERM прекращает приём запросов, отменяет задачи и закрывает
  источник; управление динамиком не переносится в Rust-сервер панели.

Не открывайте этот IPC наружу и не передавайте его через внешний HTTP-прокси.

## Дополнительные режимы и проверки

`audio companion` остаётся отдельной явно разрешённой ограниченной сессией
камеры/усиления/маски. Он запускает Python-сервис дочерним процессом и не
предназначен для одновременной работы с надзорной серверной сессией робота.
У этой схемы есть исторически описанные ограничения при жёсткой смерти
хоста; обычный звук не требует её запуска.

```sh
python3 -m unittest discover -s tests -p 'test_audio*.py'
```

Тесты используют фейки и локальные данные, а не реальную камеру, динамик,
оплачиваемый провайдер или движение робота. Исторические акустические
измерения сохранены в `audio-live-20261018.md` и `audio-zima-20261019.md`;
их старые ROS/wake-команды не являются актуальной инструкцией запуска.
