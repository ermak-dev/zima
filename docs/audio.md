# Звук, речь и активация

Аудиостек работает на основном Linux-хосте и не зависит от `player_to_ros2`.
Один ROS-сервис `robot_audio` объединяет отдельные модули захвата, детектора,
сеанса речи и выхода; ASR, воспроизведение и ROS Actions не блокируют друг друга.
Ни один аудиокомпонент не публикует `/cmd_vel`. Обычный `audio run` не снимает
RoboController и не включает лидар. Отдельная явная команда `audio companion`
временно владеет питанием камеры через LDS и затем восстанавливает контроллер.

## Устройства и подтверждённые факты

- **Выход:** штатный динамик пылесоса, ALSA `hw:0,0`. Новый helper проверен
  реальным воспроизведением TTS, BUSY и отменой с подтверждением за 1,42 с.
  Штатный контроллер при тесте оставался включённым, его PID не изменился.
  Одновременное штатное голосовое предупреждение отдельно не испытывалось.
- **Вход:** камера OpenIPC, `http://cam/audio.opus`, Ogg/Opus 48 кГц моно.
  Подтверждены запись контрольной речи и её дословное локальное распознавание
  Whisper Small. На этой прошивке изменение через API само по себе не меняло
  фактический gain: понадобились YAML и reload. При измеренных +28 dB
  (`audio.volume=90`) фон −39,3 dBFS, контрольная запись −35,0 dBFS без клиппинга.
  После теста возвращены исходные `volume=40` / −1,5 dB. Дальняя/человеческая
  речь и рабочие пороги не приняты; `microphone_verified` в профиле пока false.
- Камера в проверенной конфигурации получает питание в активном режиме
  лидара. Запуск аудиосервиса сам питание не меняет. Если камера выключена,
  источник показывает недоступность; после исчерпания ограниченных повторов
  оператор может запросить новую попытку командой `robot audio listen on`.
- ALSA capture самого пылесоса не считается рабочим микрофоном.

Код и офлайн-тесты не заменяют физическую приёмку #28, выбор русской фразы и
модели #31, реальный TTS-прогон #27 или акустическую калибровку AEC #33.
Все новые живые испытания, деплой и платные API-прогоны согласуются отдельно.

## Сборка и безопасный первый запуск

ROS 2 Jazzy, `ffmpeg`, C-компилятор и библиотека ALSA нужны для соответствующих
частей. Для Speex AEC требуется `libspeexdsp.so.1`. По умолчанию все источники,
модели, выход и внешние вызовы выключены.

Собрать интерфейсы из ROS workspace, **не из `crates/`**:

```sh
source /opt/ros/jazzy/setup.bash
cd ~/robot/ros-ws
colcon build --base-paths ../ros2/robot_audio_interfaces \
    --packages-select robot_audio_interfaces \
    --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
source install/setup.bash
```

После этого из корня проекта:

```sh
bin/robot audio check-config --config config/audio.example.json
bin/robot audio run --config config/audio.example.json
# В другом терминале: источники и выход должны быть disabled.
bin/robot audio status
```

Если интерфейсы установлены в отдельный workspace, указать путь его setup:

```sh
export ROBOT_AUDIO_SETUP=/path/to/audio-workspace/install/setup.bash
```

Рабочую конфигурацию хранить, например, в `~/.config/robot/audio.json`, а не
добавлять ключи/домашние пути в отслеживаемый пример. `check-config` проверяет
схему и лимиты, но не подключается к камере, роботу или провайдеру.

### Необязательные локальные ML-библиотеки

Базовые захват, TTS-транспорт, ROS и воспроизведение не требуют ML-пакетов.
Для моделей предусмотрено отдельное окружение Python той же версии, что ROS:

```sh
python3 -m venv --system-site-packages ~/.venvs/robot-audio
source ~/.venvs/robot-audio/bin/activate
PYTHONNOUSERSITE=1 python -m pip install -r requirements-audio.txt
PYTHONNOUSERSITE=1 python -m pip install --no-deps openwakeword==0.6.0
```

Этот ONNX-only способ установки проверен на Python 3.12. Метаданные
openWakeWord 0.6.0 требуют Linux `tflite-runtime`, но выбранный здесь ONNX backend
его не импортирует. Поэтому пакет установлен отдельно с `--no-deps`, а его
ONNX-зависимости перечислены в `requirements-audio.txt`; `pip check` может
сообщать о неустановленном TFLite. TFLite backend этим окружением не поддержан.

Сами wake/ASR-модели автоматически не скачиваются. Их пути задаются явно.
Наличие импортируемой библиотеки не означает наличие подходящей русской модели.
Код openWakeWord лицензирован Apache 2.0, опубликованные предобученные веса —
CC BY-NC-SA 4.0; для выбранных артефактов проверяется отдельная лицензия.

## ROS-контракт

Пакет `robot_audio_interfaces` содержит собственную небольшую обёртку PCM:
формат, `stream_id`, последовательность, разрыв и оценочный характер времени
нужны в каждом сообщении. Одних байтов `audio_common_msgs/AudioData` для этого
недостаточно; внешний `audio_common` не требуется для сборки проекта.

| Интерфейс | Тип | Смысл |
|---|---|---|
| `/robot/audio/input/pcm` | `AudioChunk` | S16LE, 16 кГц, моно; обычно 20 мс |
| `/robot/audio/input/info` | `AudioInfo` | Фиксированный выходной формат и источник |
| `/robot/audio/input/state` | `AudioInputState` | Доступность, возраст, уровень, ошибки, подтверждённость микрофона |
| `/robot/audio/output/state` | `PlaybackState` | Реальное воспроизведение отдельно от ожидания TTS |
| `/robot/audio/output/reference` | `AudioChunk` | Порции опорного PCM после подтверждения STARTED |
| `/robot/audio/wake_word` | `WakeWord` | Событие, фраза, модель, score и диапазон отсчётов |
| `/robot/speech/state` | `SpeechState` | Состояние сеанса, готовность моделей, текущий duplex/fallback |
| `/robot/speech/transcript` | `SpeechTranscript` | Конечная команда с идентификаторами и ошибкой |
| `/robot/audio/play` | `PlayAudio` Action | Подготовленный asset, громкость, приоритет, TTL, отмена |
| `/robot/speech/say` | `Say` Action | Текст, настроенный голос, громкость, TTL, отмена |
| `/robot/audio/listening/set_enabled` | `std_srvs/SetBool` | Остановить/возобновить разрешённый конфигурацией вход |
| `/robot/audio/output/set_muted` | `std_srvs/SetBool` | Запретить озвучивание, не отключая микрофон |
| `/robot/speech/finish` | `FinishSpeech` service | Подтвердить обработку именно указанного сеанса |
| `/diagnostics` | `DiagnosticArray` | Недоступные backend, разрывы и причины fallback |

Состояние/формат latched, PCM — bounded best-effort, события и команды —
volatile, без проигрывания старого сообщения позднему подписчику. Временная
метка PCM оценочная: камера не предоставляет подтверждённого времени
экспозиции. Начальная задержка Ogg/сети/декодера и дрейф требуют измерения.
`streaming` не означает `microphone_verified` и не удостоверяет личность.

Результаты Actions: `0` — завершено, `1` — некорректный запрос/конфликт ID,
`2` — отключено/не настроено, `3` — подтверждённая отмена, `4` — ошибка,
`5` — неизвестный исход, `6` — истёк срок. Некоторые невалидные цели
отвергаются до принятия. Успех TTS/передачи файла не равен успеху воспроизведения.

Action Server использует неблокирующие ROS futures и ограниченные workers:
отмена/приватность не ждут освобождения всех потоков executor от длинных целей.
Приоритеты очереди — `0..2`; число принятых ROS целей ограничено очередью плюс
одной активной работой. Одновременно выполняется не более одного TTS-запроса.
TTL включает ожидание TTS: поздняя фраза не отправляется в динамик.

## Захват и акустическая проверка

Включить только `input.enabled` в локальной конфигурации. Используется один
HTTP-захват; все потребители получают PCM из него. `camera.netrc` должен быть
обычным файлом текущего пользователя с правами 0600 и явной записью для `cam`.
Default-запись netrc, redirects, proxy, credentials в URL/argv не допускаются.

Декодер получает Ogg через stdin. Очереди и возраст блоков ограничены,
переподключение создаёт новый `stream_id`, потери помечаются `discontinuity`.
Старое аудио не достраивает новую команду. Прослушивание можно остановить:

```sh
bin/robot audio listen off
bin/robot audio listen on
```

Короткая явная запись использует **тот же ROS-поток**, не второе подключение:

```sh
bin/robot audio record /private/path/baseline.wav --seconds 2 --timeout 8
bin/robot audio record /private/path/probe.wav --seconds 6 --timeout 12
bin/robot audio analyze /private/path/probe.wav
```

Файл создаётся с правами 0600, существующий не перезаписывается. При смене
сеанса, потере отсчётов, отмене или недописанном интервале частичный файл удаляется.
Запись по умолчанию не ведётся, постоянного сохранения микрофона нет.

Для отдельно разрешённой физической проверки нужны фон, известный звук и речь
на заданных расстояниях. Локально можно подготовить тихий эталон:

```sh
bin/robot audio reference /private/path/reference.wav
```

Команда только пишет WAV (880 Гц, 0,75 с), не воспроизводит его. После
контролируемого теста выделить участок устойчивого тона и сравнить с фоном:

```sh
bin/robot audio analyze /private/path/tone-segment.wav \
    --reference /private/path/baseline.wav
```

Сравнение проверяет SNR, уровень, клиппинг и присутствие 880 Гц; результат
имеет scope `controlled_tone_response_only`, `speech_verified` остаётся false.
Оценка предоставленных файлов не удостоверяет их физическое происхождение.
Флаг `input.microphone_verified` не следует включать по одной доставке пакетов
или синтетическому тесту: нужна подтверждённая акустика и проверка речи.

## Воспроизведение и OpenRouter

Новый helper — обычный ARM/glibc-2.19 executable; экспериментальный LD_PRELOAD
не используется. Сборка не касается робота:

```sh
bash bin/audio/build.sh --output ~/.cache/robot/build/robot-audio-arm
```

**Следующая команда меняет файл на роботе и требует отдельного разрешения:**

```sh
bin/robot audio deploy --binary ~/.cache/robot/build/robot-audio-arm --confirm
```

Она атомарно устанавливает файл из `output.helper`, не запускает его,
не трогает контроллер и ничего не воспроизводит. `run` сам deploy не делает.
После разрешённой установки включить `output.enabled` в локальной конфигурации.

Подготовить уведомление и использовать напечатанный SHA256 asset ID:

```sh
bin/robot audio import /path/to/notification.wav --config ~/.config/robot/audio.json
bin/robot audio play <asset-id> --volume 0.35 --ttl 5
bin/robot audio stop
```

Формат нормализуется в 16 кГц/моно/S16LE, длительность не больше 30 с.
Asset-кеш приватный, имеет TTL; URL, traversal и произвольный shell не принимаются.
`stop` запрашивает отмену; окончательное подтверждение приходит результатом
исходного Action после остановки и восстановления микшера.

На роботе один собственный playback под lock. BUSY не приводит к убийству
чужого процесса. Parent guard сохраняет полный снимок микшера, наблюдает за
worker и восстанавливает его после завершения, отмены и SIGKILL worker.
SIGKILL самого guard/потеря питания не покрываются гарантией восстановления.
При недоказанном исходе SSH возвращается `unknown`, без автоматического повтора;
активация от потенциально ещё звучащего выхода подавляется до проверки/рестарта
сервиса. Работа при включённом штатном RoboController проверена; одновременную
штатную голосовую фразу ещё необходимо испытать отдельно.

Для TTS явно задать `tts.enabled=true`, `allow_external=true`, выбранные `model`
и `voice`, а также включить выход. Конкретная модель должна поддерживать
аудиовыход и русский язык; модель/голос не выбираются скрыто. Ключ — в приватном
`tts.api_key_file` (0600). Для `OPENROUTER_API_KEY` оставить `api_key_file` пустым.
Можно явно задать `tts.env_file`: из приватного обычного файла читается только
`OPENROUTER_API_KEY`, без shell/source, расширений и импорта GitLab-переменных.
Загрузчик `robot bug` не меняется. Файл должен принадлежать пользователю и не
иметь группового/публичного доступа.

```sh
bin/robot audio say --text-file /private/path/reply.txt --ttl 45 --timeout 75
```

Адаптер использует OpenRouter `/api/v1/chat/completions`, `stream=true`,
`modalities=[text,audio]` и выбранный голос. Формат задаётся в `tts.audio_format`:
`wav` либо `pcm16`. **Для проверенной `openai/gpt-audio-mini` потоковый WAV
отклоняется провайдером; нужны `pcm16`, `pcm_sample_rate=24000`, voice `alloy`.**
Частота сырого PCM — явный параметр профиля провайдера, не автоопределение.
Результат оборачивается в WAV и нормализуется для устройства.

Задание передаётся как JSON `read_verbatim`, а не реплика разговора. В runtime
по умолчанию `require_verbatim=true`: расшифровка провайдера должна совпасть с
заказанным текстом после нормализации регистра/пунктуации. Отсутствие расшифровки
или разговорный ответ дают ошибку до постановки звука в очередь. Числа лучше
передавать словами: сравнение не превращает цифры в произношение. Проверка
расшифровки не заменяет независимое акустическое распознавание; в живой проверке
эталон дополнительно распознан локальной Whisper.

`max_output_tokens` ограничивает генерацию (по умолчанию 512); обрезка `length`
не считается успешным аудио. `last_usage` содержит только возвращённые числовые
счётчики/стоимость и очищается перед каждой попыткой. Нет автоматических платных
повторов. Redirect не получает Bearer-токен. Внешнему API передаётся только
разрешённый текст озвучивания, не микрофон, кадры или карта.

В живой проверке полный ROS Say синтезировал фразу за 2,76 с; стоимость этого
запроса $0,0001974. Все завершённые генерации испытания суммарно $0,0008154
по provider usage. Детали, включая обнаруженные и исправленные ошибки —
[audio-live-20261018.md](audio-live-20261018.md).

## Wake word, русский язык и ASR

Включённый `wake` требует локальный manifest и все ONNX-артефакты:

```json
{
  "schema_version": 1,
  "phrase": "ФРАЗА_ВЫБИРАЕТСЯ_ПОЛЬЗОВАТЕЛЕМ",
  "language": "ru",
  "model_file": "wake.onnx",
  "melspec_model_file": "mel.onnx",
  "embedding_model_file": "embedding.onnx",
  "license": "ЛИЦЕНЗИЯ_ФАКТИЧЕСКИХ_ВЕСОВ",
  "verified": false
}
```

Это шаблон, не обученная модель. Для технического английского прототипа можно
использовать существующие английские веса с корректной лицензией. Готовая
английская модель не становится русской от изменения строки `phrase`.

CPU-детектор объединяет блоки в 80 мс (1280 отсчётов), хранит 1–2 с pre-roll,
применяет порог/debounce, сбрасывается при разрыве и не использует интернет/GPU.
Активировать реальный голосовой тракт разрешено только при подтверждённом
микрофоне. ASR использует локальный каталог faster-whisper, `local_files_only`;
текущая конфигурация CPU/int8. Модель не скачивается по имени.

Оценка русского решения требует выбора фразы и раздельных записей разных
говорящих/условий. Dataset JSON содержит `schema_version=1`, `phrase`,
`language`, критерии `max_false_activations_per_hour`, `max_miss_rate`,
`max_latency_s` и записи:

```json
{
  "id": "sample-1",
  "recording_id": "original-recording-1",
  "speaker_id": "speaker-1",
  "path": "sample-1.wav",
  "split": "test",
  "condition": "lidar",
  "events": [{"start": 1.2, "end": 2.0}]
}
```

WAV должен быть 16 кГц/моно/PCM16 внутри каталога датасета. Исходная запись,
говорящий, путь или одинаковые байты не могут пересекать train/validation/test.
Для отрицательных фрагментов `events=[]`; идентификаторы источников должны
отражать реальные независимые записи, а не скрывать утечку между splits.

```sh
# Только проверка разметки, без выдуманных метрик модели:
bin/robot audio evaluate /private/dataset/manifest.json
# Выбор порога только на validation:
bin/robot audio evaluate /private/dataset/manifest.json \
    --wake-manifest /private/model/manifest.json --calibrate
# Итоговая проверка неизменённого порога на test:
umask 077
bin/robot audio evaluate /private/dataset/manifest.json \
    --wake-manifest /private/model/manifest.json --threshold 0.5 --split test \
    > /private/model/evaluation.json
```

Отчёт содержит FA/hour, пропуски, задержку, условия и SHA256 всех трёх моделей.
Для русского выпуска нужны `verified=true`, `evaluation_report` с `accepted=true`,
`split=test`, совпадающими фразой/языком/артефактами. Рабочий порог должен совпасть
с проверенным. Отчёт validation не является допуском test.

### «Привет, Зи́ма»: экспериментальная модель

Пользователь выбрал обращение **«Привет, Зи́ма»**, с ударением на первом слоге.
«Привет, Зима́» — отрицательный пример. Лексическая нормализация убирает знак
ударения для сопоставления текста, но акустическая разметка хранит оба варианта
отдельно: ASR сам по себе не доказывает правильность ударения.

Подготовлены приватный синтетический датасет и ONNX-классификатор поверх
openWakeWord. Обучение использует только train; scaler встроен в ONNX.

```sh
bin/robot audio train /private/dataset/manifest.json \
    --features-dir /private/feature-models --output /private/new-model \
    --window-frames 24 --kind logistic
```

Нужны `scikit-learn` (уже в `requirements-audio.txt`), дополнительный
`onnx==1.16.2` и локальные feature-модели. Установить ONNX в активированное
ML-окружение: `PYTHONNOUSERSITE=1 python -m pip install onnx==1.16.2`;
сохранить `numpy<2`, как в requirements.
Команда не скачивает модели, не вызывает TTS и не перезаписывает существующие
веса. Для положительных тренировочных записей необходимы явные
`spoken_pronunciation` и `pronunciation_verified=true`.

Прототип хранится вне Git в `~/.local/share/robot/models/privet-zima-20261019`.
На синтетических validation и test получено по 3/3 обнаружения при пороге 0,6,
без ложных срабатываний на коротких отрицательных фрагментах. Это **не** оценка
человеческой речи или бытового FA/hour: обучающая синтетическая речь одного
голоса, независимого test-голоса с неправильным ударением нет.
`verified=false` сохранён. Запуск требует явного `--experimental-wake`;
без него русская модель отвергается. Даже экспериментальный запуск проверяет
held-out отчёт, хеши артефактов, произношение и совпадение порога.

### Ограниченная сессия камеры и ответ о заряде

```sh
# Только после разрешения на временную передачу управления режимами робота:
bin/robot audio companion --config ~/.config/robot/audio-zima-lab-20261019.json \
    --experimental-wake --max-seconds 300 --startup-seconds 120 --gain 90
```

Это не фоновый автозапуск. Команда требует включённого штатного контроллера,
локально блокирует параллельные сессии, снимает контроллер, ждёт подтверждения
`mask hold 10f8ff`, загрузки камеры и gain. Камерный guard самостоятельно
возвращает исходный gain по TTL; штатное завершение сначала останавливает
аудиопроцесс, затем проверяет gain, возвращает standby и включает контроллер.
**SIGKILL хоста или потеря питания не гарантируют возврат RoboController:**
аварийный mask guard возвращает только standby. Маска включает LDS и колёса,
но голосовой контроллер никогда не отправляет скорости; щётки выключены.

Необязательный `controller.enabled` включает только read-only ответчик о
заряде. `bin/robot battery` читает `power:0` с ограничением времени, без подписки
на привод. Если возраст измерения неизвестен, обычный ответ отказывается
утверждать текущий заряд. Явный `allow_reported_battery=true` разрешает ответ
с оговоркой «Робот сообщает… Давность измерения неизвестна».

Ответчик принимает только финальные транскрипты, устраняет повтор по
`session_id` и завершает неподдерживаемые команды без исполнения.
`cache_only=true` запрещает генерацию: `reply_cache` сопоставляет точный текст
SHA256 asset ID. Если заряд изменился и соответствующего ответа нет, возникает
`reply_cache_miss`, а не неверный ответ из кеша. Файлы кеша имеют TTL.
Обычный пример конфигурации оставляет этот контроллер выключенным.
Результаты и ограничения прототипа: [audio-zima-20261019.md](audio-zima-20261019.md).

## Сеанс, тишина и эхоподавление

Состояния: `waiting → listening → transcribing → processing → speaking → waiting`,
с явными fault/cancel. Pre-roll сохраняет начало просьбы без паузы после
обращения; VAD/таймауты ограничивают ожидание/длительность. Текущий `RmsVad` —
энергетический baseline, не нейронная классификация речи: порог требует оценки
на реальном фоне. Порог задаётся `speech.vad_threshold_dbfs` (исходно −40 dBFS).
При усилении микрофона надо калибровать его заново относительно шума лидара;
в тестовом профиле задан пробный −35 dBFS, не универсальный порог. ASR-worker
один, поздние результаты отменённого сеанса игнорируются.

После transcript контроллер проверяет полномочия и либо отвечает через `say`,
либо подтверждает обработку без речи через `/robot/speech/finish` с тем же
`session_id`. Модуль сам не исполняет команды. Телевизор/голос/score не являются
удостоверением владельца, голосовой Stop не заменяет независимую защиту.

Первая версия полудуплексная: ожидание TTS не блокирует активацию как звучащий
динамик, но фактическое воспроизведение и измеренный хвост подавляют её.
Отмена через контроллер/панель остаётся доступной; голосовое barge-in по
умолчанию выключено. `audio listen off` останавливает захват и очищает сеанс.
`robot audio mute on/off` и `/robot/audio/output/set_muted` меняют только политику
динамика, не отключая микрофон. При mute новые запросы не вызывают платный TTS,
активный выход получает отмену; физическое завершение подтверждается отдельно
результатом Action. В `output.muted` задаётся начальное значение, в
`output.quiet_hours` — до восьми ежедневных окон вида `22:00-08:00`, в
`output.timezone` — явная IANA-зона. По умолчанию расписание пустое, зона UTC;
зону дома надо выбрать явно. Переход через полночь поддержан, одинаковые
концы окна отвергаются. При наступлении тихого интервала выход отменяется,
но это не означает мгновенной физической тишины до подтверждения остановки.

Для full-duplex реализован настоящий SpeexDSP (20 мс, 16 кГц), ограниченная
опора воспроизведения и проверка задержки/дрейфа. Опора начинается только после
helper STARTED, но SSH-метка всё ещё оценочная. Нужны физическая калибровка,
`echo.enabled=true`, `echo.verified=true` и `speech.mode=full_duplex`.
Без совпадающей опоры/при разрыве/дрейфе выполняется явный half-duplex fallback.

При подтверждённой активации во время ответа отмена ожидается асинхронно;
ограниченный буфер сохраняет начало новой команды. ASR-сеанс начинается только
после подтверждённого окончания/отмены выхода. Неизвестный результат не
выдаётся за успешное прерывание. Опора штатных фраз RoboController не доступна
автоматически; подавление этих фраз и реальное double-talk требуют отдельной проверки.

## Проверки

```sh
source /opt/ros/jazzy/setup.bash
source ~/robot/ros-ws/install/setup.bash
python3 -m unittest discover -s tests -p 'test_audio*.py' -v
shellcheck bin/robot bin/audio/build.sh
```

Для отдельного тестового overlay выставить `ROBOT_AUDIO_SETUP`. ROS-тесты
используют отдельные DDS-домены, локальные источники/модели/провайдеры/SSH-фейки.
Проверяются реальные ffmpeg и SpeexDSP, сгенерированные ROS-типы, Actions,
конкурентная отмена, полный цикл PCM → wake → ASR → TTS → воспроизведение,
приватность файлов, отказы, guard и восстановление микшера на fake ALSA.
Новые команды не запускают движение/сессии робота как побочный эффект.

Офлайн-тесты сами по себе не принимают физические устройства. Живые результаты
нового helper, OpenRouter и локальной Whisper записаны отдельно. Русские wake-веса,
дальняя речь, реальные near-end/double-talk и акустический AEC пока не приняты.
